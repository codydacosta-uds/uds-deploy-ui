# Development rules

- Keep this a small, read-only viewer. No CLI replacement/registration, native bootstrap binaries, services, database, telemetry, deployment launching, retries, cancellation, scheduling or mutation APIs.
- Only the explicit, path-free `install.sh`/`uninstall.sh` may manage the `~/.local/bin/uds-watch` symlink and marked Bash/Zsh function for `uds watch` and capture of plain `uds deploy`/`uds d`. Never install automatically on viewer startup, replace UDS, intercept other commands, or edit deployment task files. Keep these scripts minimal and idempotent.
- Capture belongs to the shell function or explicitly wired deployment tasks. The existing tee copies stdin and preserves original bytes; the shell/task owns the native CLI and its exit status. The viewer reads only same-user process metadata, packaged artifacts and validated private capture files. Never read a deployment's TTY, history or output pipe.
- Python runtime stays stdlib-only; the frontend stays build-free with local assets. Never save resolved external credentials/config, decoded Helm values or kubeconfig. Full packaged YAML remains visible.
- Preserve the approved terminal-health inference: complete sequential capture, reported Helm health checks, then CLI termination without reported errors can show Done. All declared components/all observed work must be covered for package/run Done. Explain inference. Errors, retries, gaps, failed current-deployment checks, concurrent/ambiguous streams or silence/disappearance alone must not pass.
- The approved integrated viewer's `uds-deploy-ui` branch (`scripts/uds_deploy/web/`) is the UI source of truth. Standalone `src/uds_deploy/web/` is a verbatim vendor copy. Keep all shared assets byte-identical using `scripts/sync-ui.py`, `ui-assets.json` and parity checks; never independently restyle or merely regenerate pins to conceal drift.
- Keep shared `uds_deploy/output.py` bytes and `capture-protocol.json` identical in producers/readers. Use only the configured generic capture namespace. Never migrate or delete live capture files.
- Verify affected UI with actual captures, normal Playwright launch/default safety flags, both themes and responsive widths. Label isolated fixtures honestly. Never launch an OS browser with fake HOME or operate on Keychain. Browser handoff recording is not OS integration certification.
- Keep tests isolated. No real application/cluster deployments for testing. Never restart/stop existing viewers or lose their held logs. Clean up only owned fixtures, servers and browsers.
- Use Conventional Commits and PR titles. Work on feature branches; never update or merge the default branch. No secrets, captures, CLI binaries, private URLs or machine paths in public changes.
